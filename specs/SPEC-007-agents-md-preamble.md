# [SPEC-007] Feature: AGENTS.md preamble injection

## Overview

`sync-agents index` regenerates `AGENTS.md` in full, so any hand-authored content in that file is silently destroyed on the next run. This SPEC adds a **preamble**: a hand-authored markdown file living in the global agents tree, which `index` reads and injects into the generated `AGENTS.md`. The generated file remains 100% generated — the preamble's source of truth is a separate, version-controlled file owned by the agents repo.

## Motivation

This is a real data-loss incident, not a hypothetical. On 2026-08-10 a user added 159 lines of engineering principles to `AGENTS.md` in the `@agents` repo. `AGENTS.md:6-7` warns "Auto-generated by sync-agents. Do not edit manually", but the warning is easy to miss and there is no guard — the next `index` run deletes the content with no error, no diff, and no backup.

Verified empirically by copying the repo to a scratch directory and running `sync-agents index` against the copy: **251 lines → 92 lines**, all 159 added lines gone.

The underlying need is legitimate: the user wants a body of engineering principles that is *owned by the agents repo*, version-controlled, and propagated everywhere the agents tree reaches. Today there is nowhere to put such content except the generated file that destroys it, or a per-machine `~/.claude/CLAUDE.md` that the agents repo does not own.

## Goals

- Allow hand-authored global content to appear in generated `AGENTS.md`.
- Keep the source of truth in a version-controlled file inside the agents tree.
- Keep `AGENTS.md` fully generated, so "do not edit manually" stays unambiguously true.
- Fail safe: a missing preamble file is not an error.

## Non-Goals

- **Preserving hand edits made directly in `AGENTS.md`.** That is the rejected alternative (see Design). `AGENTS.md` remains disposable output.
- **Per-project preambles.** Resolution is global-only in this SPEC.
- Templating, variable substitution, or conditional inclusion. The preamble is copied verbatim.
- Any change to how rules, skills, or workflows are indexed.

## Definitions

- **Preamble** — a markdown file whose contents are injected verbatim into generated `AGENTS.md`.
- **Global agents tree** — the user-scope `~/.agents/` directory (or `$SYNC_AGENTS_GLOBAL_ROOT`, or `--global-root`).

## Design

### Chosen: inject a preamble file at generation time

`index` reads the preamble from the global agents tree and writes its contents into the generated `AGENTS.md` between the header and the `## Rules` section. `AGENTS.md` stays entirely machine-generated.

### Rejected: managed block inside AGENTS.md

The alternative was to mark a region of `AGENTS.md` with HTML-comment fences and have `index` rewrite only outside them — mirroring `internal/agent/managedimport.go`, which already implements exactly that pattern with `ManagedImportBlockStart` / `ManagedImportBlockEnd` and preserves content outside the markers.

Rejected despite reusing more existing machinery, because it makes `AGENTS.md` partly generated and partly hand-authored. Some edits would survive and others would silently vanish depending on where the cursor happened to be relative to a fence. That is a worse failure mode than today's "no edits survive", and it is a more confusing version of the exact trap that motivated this SPEC. Keeping the invariant absolute — *nothing* in `AGENTS.md` is hand-authored — is the safer contract.

### Resolution: global only

The preamble is read from the global agents tree only, at `<global-root>/AGENTS.preamble.md`. There is no per-project preamble and no per-project override. An `AGENTS.preamble.md` sitting in a project's local `.agents/` directory is ignored. This was confirmed during review on 2026-08-10: resolution is global only.

### Placement

The preamble is injected after the auto-generated header and the index description line, and before the `## Rules` section — the position the content was hand-placed in during the incident that motivated this SPEC.

## Requirements

### Requirement: Preamble injection

`index` SHALL inject the contents of `<global-root>/AGENTS.preamble.md` into generated `AGENTS.md` when that file exists.

#### Scenario: Preamble present

- **GIVEN** `~/.agents/AGENTS.preamble.md` exists and contains `# Engineering Principles`
- **WHEN** `sync-agents index` runs
- **THEN** the generated `AGENTS.md` contains `# Engineering Principles`
- **AND** the content appears after the header and before `## Rules`
- **AND** the `## Rules`, `## Skills`, and `## Workflows` sections are unchanged

#### Scenario: Preamble absent

- **GIVEN** no `AGENTS.preamble.md` exists in the global agents tree
- **WHEN** `sync-agents index` runs
- **THEN** `AGENTS.md` is generated exactly as it is today
- **AND** no warning or error is emitted

#### Scenario: Preamble is empty

- **GIVEN** `~/.agents/AGENTS.preamble.md` exists but is zero bytes
- **WHEN** `sync-agents index` runs
- **THEN** `AGENTS.md` is generated as if no preamble existed
- **AND** no stray blank sections are introduced

#### Scenario: Injection is idempotent

- **GIVEN** a preamble exists
- **WHEN** `sync-agents index` runs twice in succession
- **THEN** the second run produces a byte-identical `AGENTS.md`
- **AND** the preamble content appears exactly once

#### Scenario: Preamble content is copied verbatim

- **GIVEN** a preamble containing markdown headings, lists, code fences, and HTML comments
- **WHEN** `sync-agents index` runs
- **THEN** the injected content is byte-identical to the source file
- **AND** no escaping, reflowing, or heading-level rewriting occurs

### Requirement: Global-only resolution

`index` SHALL resolve the preamble from the global agents tree only.

#### Scenario: Project-local preamble is ignored

- **GIVEN** a project has `.agents/AGENTS.preamble.md` containing `LOCAL`
- **AND** no preamble exists in the global agents tree
- **WHEN** `sync-agents index` runs in that project
- **THEN** the generated `AGENTS.md` does NOT contain `LOCAL`

#### Scenario: Global root override is honored

- **GIVEN** `--global-root` points at a directory containing `AGENTS.preamble.md`
- **WHEN** `sync-agents index` runs with that flag
- **THEN** the preamble from the overridden root is injected

### Requirement: Dry-run safety

`index --dry-run` SHALL NOT write to disk.

This is a bug fix carried by this change, confirmed in review on 2026-08-10. `CmdIndex` calls `generateAgentsMD()` unconditionally without consulting `a.DryRun`, so `sync-agents index --dry-run` rewrites `AGENTS.md` and reports "Regenerated AGENTS.md" as though it had not. The bug predates this SPEC and is still present as of v0.3.6, but the preamble feature makes it materially more dangerous: a user who runs `index --dry-run` to preview the effect of a preamble would silently overwrite the real file.

#### Scenario: Dry-run does not write

- **GIVEN** a preamble exists
- **AND** `AGENTS.md` is currently out of date with respect to the agents tree
- **WHEN** `sync-agents index --dry-run` runs
- **THEN** `AGENTS.md` on disk is byte-identical to what it was before the command
- **AND** the command reports what it would have written rather than claiming it regenerated

#### Scenario: Dry-run reports the preamble it would inject

- **GIVEN** a preamble exists in the global agents tree
- **WHEN** `sync-agents index --dry-run` runs
- **THEN** the output indicates that a preamble would be injected
- **AND** no file is modified

## Code being removed

None. This change is purely additive — no existing exports, files, or behavior are superseded.

## Verification plan

- Unit tests for preamble resolution and injection, alongside the existing `internal/agent` tests.
- Manual end-to-end check by building the binary to a scratch path and running it against a disposable copy of an agents repo, never against a live tree.
- Confirm the byte-identical idempotence scenario explicitly, since it is the property that makes the generated file safe to commit.

## Resolved questions

All three questions raised in the first draft were answered in review on 2026-08-10.

1. **Resolution scope.** The preamble resolves from the global agents tree only. There is no per-project preamble and no per-project override.
2. **Dry-run correctness.** The `--dry-run` fix is carried by this change rather than deferred to a separate one.
3. **Filename.** The preamble file is named `AGENTS.preamble.md`.
